Dokument ist der Beleg, dass die Fläche geprüft wurde, samt PASS-Listen und den

Lücke. Zwei Befunde der AU2-/GDPR-Klasse behoben (Details im COMPLETE-Eintrag

## Schnitt A — billing + tickets (control-Instanz)

Behoben: `POST /api/billing/checkout`+`/portal` und `POST /api/tickets/:id/files`
in `WRITE_LIMITED` nachgetragen (Drossel-Lücken).

PASS: Stripe-Webhook (raw-body `constructEvent`, Allowlist, idempotenter Upsert
per `stripeSubscriptionId` + Stale-Guard, Verarbeitungsfehler werfen 500 für
Stripe-Retry, No-op/Mapping-Miss geben 200) · `shouldLiftBillingSuspension` nur
bei `active`, abuse unangetastet · Zahlungswarnung-Scope (account vs. tenant/A6)
korrekt, Idempotenz-rowId im Sweep · Cross-Account-Scoping (jeder Read per
userId/subId, Upsert bewahrt `existing.userId`) · Stripe-Keys AES-verschlüsselt,
Row-Permissions leer, kein Key im Log/Client · GDPR-Contributor billing+tickets
(inkl. Stripe-Kundenlöschung) · Ticket-RBAC (`tickets.manage`, AI-Edit auf
`system.manage` eskaliert) · Ticket-Datei-Sicherheit (Magic-Bytes + 10 MB,
Download permission-gated, safe Content-Disposition) · Query.limit überall.

## Schnitt B — events + courses + media (Pool)

Behoben: RSVP/Score/Cover/Enroll/Lesson-Complete-Drosseln; courses
GDPR-Delete-Swallow strikt gemacht.

PASS: Datentür + kein rohes `.tablesDB` (ESLint-Backstop deckt alle drei) ·
actor:'member' auf allen Inhalts-Schreibwegen (M13/A5), withdraw/cancel bewusst
ohne actor · stripTenantKey · Pool-Unique `uq_tenant_slug` · Upload-Härtung

Publikums-Gate (eingeloggt vs. Gast), bewusst so, damit der Katalog VOR dem
Beitritt sichtbar ist.

## Schnitt C — messages + pages + analytics

# Runde 6 (nachmittags) — die LETZTEN ungeprüften Layer: admin, moderation, themes, feedback, domains

## Schnitt D — admin + moderation (Betreiber-Konsole + Melde-System)

Keine Sicherheits-/RBAC-/Isolations-Lücke. PASS: alle 40 admin-Routen gegatet
(Schreibrouten label-only, nur 3 Lese-Aggregate über Site-Rolle
`dashboard.access`) · `requirePermission` liest server-seitig NUR `user.labels`
(verifiziert) — kein Site-Owner erreicht eine admin-Daten-API · Rollen-Route
erzwingt `actorCaps ⊇ role.caps` und lässt nur `admin`/`moderator` zu (nie
owner), plus kein Selbst-Entzug + `assertNotLastAdmin` (verifiziert) — keine
Privilege-Escalation · Config gibt nur `toPublicAppConfig` (kein Secret) ·
Pool-User-Leak-Guard (search/stats überspringen Pool) · Moderation isoliert
über die Operator-Tür + `reports.moderate`, Report-Row-Publikum nur
Moderatoren+Melder · N7-Changelog-404 · GDPR-Contributor · `system/update`
dev-only + Whitelist.

Zwei Nicht-Defekte: (a) **[Low/UX]** `admin/app/middleware/admin.ts:37` lässt
die Nutzerverwaltungs-SEITE für eine Site-Rolle rendern, die die Capability in
ihrer Matrix trägt — aber jede Server-Route ist label-only, also 403; schlimmster
Fall ist ein LEERER Operator-Screen, keine Daten. (b) **Bekannte Drift**:
admin→comments String-Kopplung (`tableId: 'comments'`, 3 Server + 1 Client, von
historisch 9× runter) — alle mandanten-gescopt (Operator-Tür / `useRealtimeRows`
mit communityId), kein Isolationsrisiko; wartet auf einen expliziten
moderation/comments-Vertrag (A14).

## Schnitt E — themes + feedback + domains

Keine Defekte. **Theme-Stored-XSS/CSS-Injektion ist fail-closed** (defense-in-
depth am Render-Punkt, unabhängig von der Schreibgrenze): Farben nur Hex aus dem
OKLCH-Generator, `attr`/Varianten-Id/Font-Name/Font-Id über Allowlists
(`SAFE_ATTR`, `SAFE_VARIANT_ID`, `SAFE_FONT_NAME`, `SAFE_ID`), radius/tracking/
weight numerisch/boolesch geprüft — ein `</style><script>` in irgendeinem Feld
ergibt `return ''`. feedback/domains sind dünne, korrekt gegatete Proxys zum
Control Plane (`dashboard.access`/`feedback.manage`/`community.domain`,
Envelope aus dem Server-Kontext nie aus dem Body, control-Callback per
`timingSafeEqual`). Rate-Limits (feedback:create 5/min etc.), GDPR-Contributor,
i18n, localePath: alles PASS.

Offene Frage (an den admin/system-Auditor weitergereicht, hier bestätigt): die
Theme/Font-SCHREIB-Autorisierung liegt in admin/system (themes hat kein
`server/`) — der Render-Sink ist aber ohnehin fail-closed, ein fehl-gescopter
Schreiber erreicht damit höchstens eine unbefugte Theme-ÄNDERUNG, keine
Injektion. Die Sink-Allowlists spiegeln die admin-Zod-Schemas; eine Drift dort
schwächt den Sink NICHT.
